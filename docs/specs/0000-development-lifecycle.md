# 0000 Development lifecycle and the editor shell

Status: **spec** (frozen when its PR opens). Date: 2026-10-29. Decided by: the operator's assignment of 2026-10-29 (a lifecycle "as tsukuri's spec 0000", a scaffolded Foldkit app that renders a placeholder shell, branch protection like tsukuri's).
Binding for: every later PR in this repository. Implemented by the PR that carries this file.
Mirrors: [tsukuri spec 0000](https://github.com/tsukuri-labs/tsukuri/blob/main/docs/specs/0000-development-lifecycle.md) at `f7c348877585f54b6bf00651608726dd7e5044d3`. Read it for the reasons; this file records what is the same, what is different and why.

## Goal

Every change to tsukuri studio travels one road: **spec → code → PR**, strictly 1:1, and no change reaches `main` without passing the same gates locally, in CI and in a recorded review round. The road is the one tsukuri built (Vite+, Oxlint, Oxfmt, Ultracite, `@effect/tsgo`, gitleaks, commitlint, knip, jscpd, `gh`), copied with provenance, not rewritten. On that road stands one app, `apps/editor`, a Foldkit application that renders a placeholder shell of the editor. The shell proves the toolchain end to end (generate, lint, type-check, test, bundle, run in a browser); it edits nothing.

## Journey

```text
contributor (human or agent)
  1. write or pick a spec        docs/specs/NNNN-*.md          the plan, its falsifiers, its dated Revisions
  2. branch                      feat/NNNN-<slug>              one spec, one branch, one PR
  3. commit                      pre-commit: gitleaks on the staged blobs, then `vp staged` (format and lint --fix)
                                 commit-msg: commitlint (Conventional Commits)
  4. push                        pre-push: the test suite
  5. open the PR                 skill pr-create: the PR body is the report
  6. CI                          .github/workflows/checks.yml runs the same gates as `bun run ready`
  7. review round(s)             skill review-pr: independent reviewers, severity, recorded on the PR
  8. merge                       .agents/skills/review-pr/merge.sh: refuses without a passing record on the head
```

A reader who clones the repository, runs `devenv shell -- bun install` and then `devenv shell -- bun run ready`, sees every gate pass on a clean tree. To see the shell: `devenv shell -- bun run build`, then `devenv shell -- bunx vp preview` in `apps/editor`, and open <http://localhost:4173/>: the title "tsukuri studio", four regions (Story graph, Preview, Timeline, Inspector) and a button that hides and shows the Inspector.

## Constraints and values

- Correctness by construction: a gate that can be made structural is structural (as tsukuri 0000). `main` cannot be pushed to, a PR cannot be merged without a passing recorded round on its head, an Effect package cannot drift from the `effect` version, a suppression cannot exist without a registry entry.
- One source per fact. The gate list lives in `package.json` scripts (`ready`) and the table in `AGENTS.md` names each script; CI calls the same scripts and never repeats their commands.
- Reuse, do not hand-roll. Every copied file names its source (repository, commit, deviation) in a header or in `PROVENANCE.md`; scripts are copied byte for byte so `git hash-object` proves it.
- Scaffold with generators. The app comes from `create-foldkit-app` 0.40.0 (`--rendering spa --example counter --package-manager bun`, run in a scratch directory); the toolchain files come from tsukuri, whose root was itself generated by `vp create vite:monorepo`. What is written by hand is only what no generator makes: the shell's Model, view and tests, the lint adapter for the Foldkit plugin, and the docs.
- Default stack as the operator's (TypeScript 7.0.2, Bun, Effect 4.1.0, Oxfmt, Oxlint with the Effect plugin, `@effect/tsgo` 0.63.0, Vite+ 1.2.0, devenv, Foldkit 0.169.0). Alchemy v2 is not used yet: there is nothing to deploy.
- Public repository: no secret, no personal data, no course-private material. No `LICENSE` file: the README says "source visible; all rights reserved; licence not decided".

## The shell

A placeholder, by design: it names the regions the first felt journey (spec 0001) will fill and shows no story. `Model = { inspector: Collapsed | Expanded }` is a tagged union, not a boolean (FOLDKIT.md: encode state in unions). `update` is a total function and returns no Command, so nothing runs outside the runtime; the Story tests say so with `Command.expectNone()`. The view has one `h1`, three `section` regions and one `aside`, each with an accessible name, and a button whose `aria-expanded` follows the Model.

## Falsifiers

Each falsifier has a negative control that is run and observed to fail, with the output recorded in the PR body. A control is a deliberate defect applied to a scratch copy or a throwaway branch and never committed to `main`.

| # | Falsifier (must hold) | Gate | Negative control (must fail) |
|---|---|---|---|
| F1 | `bun run ready` exits 0 on a clean tree of the PR head | `ready` | F2 to F5, F7, F10 to F12 each make `ready` or a hook exit non-zero where it is the gate |
| F2 | A commit message that is not a Conventional Commit is rejected | `commit-msg` | `git commit -m "stuff"` is refused with the commitlint reason; `git commit -m "chore: x"` is accepted |
| F3 | A lint error in a staged file blocks the commit | `pre-commit` (`vp staged`) | Stage a file with `console.log` and an `any` parameter; the commit is refused |
| F4 | A secret in a staged file blocks the commit | `pre-commit` (gitleaks) | Stage a file holding a synthetic key in a well-known format (written only to the scratch copy); the commit is refused |
| F5 | An `oxlint-disable` without a registry entry fails `check:exceptions` | `check:exceptions` | Add `// oxlint-disable-next-line <rule>` without an entry: exits non-zero and names the file and line; remove the directive again: exits 0 |
| F6 | CI runs the gates on every PR and fails when one fails | `checks.yml` | This PR shows a green `checks` run; a throwaway PR with a lint violation shows a red one (closed, not merged) |
| F7 | `effect` and every `@effect/*` package share one version | family test | In a scratch copy, change one `@effect/*` entry of `bun.lock`: the test fails and names the package |
| F8 | A PR cannot be merged without a passing recorded round on its current head | `merge.sh` | On the throwaway PR: `merge.sh` before recording exits 4; after a `changes` round exits 4; after a `pass` round and one more commit exits 4 (head moved). The final step of tsukuri's F8 (merging the passing head) is not run: this assignment does not merge |
| F9 | `main` cannot be pushed to directly | branch protection | `git push origin HEAD:main` from a scratch clone is rejected by GitHub |
| F10 | Cognitive complexity above 15 and a floating Effect fail `vp check` | Oxlint | A scratch function with complexity 16 fails; `Effect.succeed(1);` as a statement fails |
| F11 | The shell's behaviour is pinned by tests that run through the Foldkit runtime's own test harness | `bun run test` (Story and Scene) | Make `update` return the model unchanged: the Story tests and the Scene test for the toggle fail |
| F12 | The Foldkit conventions are enforced, not read | `vp check` (Foldkit plugin) | A `switch` on `message._tag` in `apps/editor/src` fails with `foldkit/no-switch-on-message-tag` |

Not gated, observed once (recorded in the PR body): the built editor, served by `vp preview` and loaded in headless Chromium, renders the heading and the four regions on Effect 4.1.0 with Foldkit 0.169.0. CI has no Chromium: adding a browser gate is a later spec.

## Constraints on the implementation

- Free on mechanism, specific on behaviour: the scripts may be arranged differently as long as `ready`, `check`, `test`, `build`, `check:exceptions`, `knip`, `cpd` and `secrets` exist and the journey above holds.
- No editing feature and no use of the story IR: spec 0001 is blocked on tsukuri 0004 and 0006.
- Tests use fixtures written to temporary directories; none reads a file outside the repository.

## Risks

| Risk | Mitigation |
|---|---|
| Foldkit 0.169.0 targets `effect@4.0.0` and this repository runs 4.1.0 | Story and Scene tests, the build and a browser smoke on 4.1.0 (Revisions 2026-10-29); bun's peer warnings are expected until a Foldkit release lists 4.1.0; the family check keeps `effect` and `@effect/*` at one version |
| `@foldkit/vite-plugin` is unusable on 4.1.0 (it imports `Crypto` from the `effect` root) | Not installed; the app builds with Vite+ and Tailwind; the plugin's dev tools, MCP bridge and hot model preservation are therefore off. Revisit when the plugin supports 4.1.0 |
| devenv in CI is slow (Nix install, cache misses) | Reuse tsukuri's pinned devenv and the `devenv` Cachix cache; measure the first run and record it in the PR |
| The exception registry becomes a rubber stamp | Each entry needs a retirement trigger and the conformance reviewer checks new entries |
| Branch protection with administrators included blocks the operator in an emergency | The command that removes it is in `AGENTS.md` |

## Revisions

Dated entries. A spec is revised only here; its text above is never edited silently after the PR opens. Before the PR opens, the plan may change freely as the build teaches; a change that alters the journey, scope or a falsifier gets an entry anyway.

- **2026-10-29, plan written** with the build: tsukuri's lifecycle copied at `f7c3488`, the app generated, the shell written.
- **2026-10-29, build deviations (found while building; none changes the journey or a falsifier).**
  1. **No `@foldkit/vite-plugin`.** The generator's Vite config uses it. Release 0.28.0 pins `effect@4.0.0` and imports `Crypto` from the `effect` root; effect 4.1.0 no longer exports it (it moved to `effect/crypto`), so Vite failed at "failed to load config" with `The requested module 'effect' does not provide an export named 'Crypto'`. The config is Vite+ with Tailwind only. Foldkit's own package (`foldkit`, `@foldkit/ui`) imports nothing that 4.1.0 lacks: the Story and Scene tests, the build and the Chromium smoke pass.
  2. **Overrides.** `@effect/platform-node` and `@effect/platform-node-shared` are pinned to 4.1.0 by `overrides` (as tsukuri does for the second), so the family check holds; `@effect/platform-browser` is a direct dependency at 4.1.0.
  3. **Formatting.** The generator writes single quotes and no semicolons; the repository's Oxfmt (Ultracite) rewrote them. The generated `.oxlintrc*.json`, `.oxfmtrc.json`, `vitest.config.ts`, `tsconfig.json`, `.mcp.json` and `README.md` were not kept: the root configuration replaces them. `src/vitest-setup.ts` became `src/vitestSetup.ts` (the repository's camelCase filename rule).
  4. **Vitest through Vite+.** Tests import `describe`, `test` and `expect` from `vite-plus/test` (lint rule `vite-plus/prefer-vite-plus-imports`), and the Vitest options moved into the `test` block of `apps/editor/vite.config.ts`.
  5. **`eslint/no-redeclare` is off for `apps/editor/src`.** Foldkit declares a Schema and its type under one name (`const Message` and `type Message`, required by `FOLDKIT.md`); Oxlint's rule does not know that TypeScript merges a value and a type. It is a configuration switch with its reason in `vite.config.ts`, not a suppression directive, so it needs no registry entry; the TypeScript checker still rejects a real redeclaration.
  6. **The Foldkit lint adapter.** `@foldkit/oxlint-plugin/recommended.json` is JSON, so its severities are typed `string` and the Oxlint config types reject them. `tools/quality/foldkitLint.ts` maps `off` to `off` and every other value to `error` (a new severity never weakens a rule) and has its own test.
  7. **`devenv.nix`** has no Chromium, ffmpeg or whisper; the browser smoke used the machine's `chromium` on `PATH`.
  8. **`apps/editor/AGENTS.md`** sets `subtree_prompted: true` and says why the subtree is not vendored.
  9. **One copied test changed.** `tools/quality/test/effectFamily.test.ts` had a control that deletes a version key from the first record of the exception registry and asserts it is reported; tsukuri's registry has records, this repository's is empty, so the test failed on `assert.isDefined(first)`. The control now falls back to a fixture record that names the locked versions (a record the lock agrees with), so it still fails when the check stops reporting a missing key, and it uses a real record when one exists. Every other copied test is unchanged.
  10. **`src/testModels.ts`.** `bun run cpd` (threshold 0) found the two model fixtures duplicated in the Story and Scene tests; they moved into one module.
  11. **`knip.json`** lists no `vite` ignore and no entry for `src/entry.ts` or `src/vitestSetup.ts` (knip finds both through the Vite and Vitest configs); `src/styles.css` is outside its project because only `index.html` links it.

The issue to re-enable it, with the exact error, the release to wait for and the steps, is [tsukuri-labs/studio#4](https://github.com/tsukuri-labs/studio/issues/4). All rights reserved; licence not decided.` (his full legal name, with the ø; no organisation number), then says the source is visible and that no licence file is present on purpose. - **2026-10-29, the runtime boot is gated (round 2 finding, low).** `apps/editor/src/boot.test.ts` boots the real application in happy-dom on effect 4.1.0: `Runtime.run` renders the shell into a container and a click hides the Inspector; `Runtime.embed` renders and its `dispose` removes the app and leaves the container empty. That gates the Foldkit 0.169.0 peer mismatch (`effect@4.0.0`) at the place it would show, without Chromium; the Chromium smoke stays not gated. To make the boot testable `apps/editor/src/application.ts` builds the application from a container, `entry.ts` only runs it, and the new test imports `@effect/vitest` (a devDependency of `apps/editor`). Findings from writing it: a Foldkit container needs an `id` (without one the runtime logs an error and renders nothing), and the first render replaces the container element, so a test holds a wrapper around it. Without `@foldkit/vite-plugin` the dev server, where `import.meta.hot` exists, logs "No response from @foldkit/vite-plugin" and waits 500 ms (`PLUGIN_RESPONSE_TIMEOUT_MS`) before the first render; a production build does not (recorded in issue #4).
